# XMall 发行与升级说明

## v1.4.0 更新

本版基于 v1.3.0，聚焦内置 Telegram 购物体验与实例运营能力：

- 购物面板改为原地编辑：浏览、选购、支付、订单在同一条面板消息内切换，减少刷屏。
- 分类与商品分区展示；主操作、确认支付、取消等按钮使用 Telegram 彩色样式（旧客户端忽略颜色，功能不受影响）。
- 支付面板强化「查询结果 / 取消」文案与布局；下单与支付仍寄生商城订单、支付、钱包域，不直连上游网关。
- 实例资料支持展示名、简介与头像同步（含静态图与动态头像）；菜单、群发等运营能力继续按实例配置。
- 取消旧 Bot 客户端历史归属与导入/接管链路；创建、配置和运行原生实例不再受旧渠道记录阻塞。
- 保留 Telegram 身份校验、同 Bot 单实例约束、配置版本校验、运行租约和 webhook 检查；不自动启用实例或删除业务数据。
- v1.3.0 文档中的显式接管说明仅适用于该已发布版本，本版及之后源码不再提供这些接口。

## 从 v1.3.0 升级

1. 备份数据库、运行配置、上传文件和使用中的 Redis 队列；保存原版本二进制。
2. 若仍依赖旧客户端管理 API 或 v1.3.0 接管接口，先完成管理工具迁移。不要通过直接改库绕过校验。
3. 从本项目 Release 下载匹配系统与架构的安装包，核对 SHA-256 校验和。不要用示例配置覆盖原配置，尤其不要随意更换存量加密密钥。
4. 停止旧进程或按既有后台升级流程替换二进制，然后显式重启。面板托管部署需核对进程状态和日志，不将二进制替换成功视为服务已经重启。
5. 检查版本、`/health`、商城、自定义后台路径、登录与角色权限；按实际启用模块验收订单、支付、Telegram 实例购物与异步任务。
6. 回滚前核对数据兼容性；恢复二进制不等于恢复数据库。必要时使用对应备份恢复，并避免重复消费队列或重复履约。

内置 Telegram Bot 和异步任务需要可用 Redis 与启用的队列。仅 API、队列关闭的部署使用 `./xmall -mode api`；默认 `all` 模式不能在队列关闭时使用。

## v1.3.0 更新

本版基于 v1.2.0，主要整理 Telegram 后台入口与旧客户端管理能力：

- 将 Telegram Bot 概览统一为「机器人实例管理」，合并重复的连接状态入口。
- 旧连接状态、Bot 客户端页面地址自动跳转到实例管理，继续执行登录和角色权限校验。
- 移除旧 Bot 客户端管理页面、前端 API、`/api/v1/admin/channel-clients` 管理接口及对应内置角色权限。
- 保留实例运行、历史身份、显式接管和外部业务兼容链路，不删除存量数据表，不自动撤销外部客户端凭据。
- 更新部署与维护文档，取消 Docker 镜像内测和发布工作流；官方发行继续提供多平台安装包。原有 Dockerfile 仅供自行构建。

## 维护者发行流程

1. 审阅代码和升级说明，执行发布输入检查并等待目标提交 CI 通过。
2. 确认目标版本标签尚未占用，对已验证提交推送独立的 `v*` 标签；不移动旧标签或覆盖旧发行物。
3. `release.yml` 通过 GoReleaser 执行后端/前端测试与构建，生成 Linux、Windows、macOS 的 amd64 / arm64 安装包和校验和，创建草稿 Release。
4. 检查草稿附件数量、文件名、校验和、归档内容及构建提交，补充本版变更和升级注意事项，再公开草稿。
5. 正式发布与生产升级分开执行。CI 和产物校验不替代目标服务器、真实支付或 Telegram 业务验收。

不再发布官方 Docker 镜像，不需要 GHCR 配置或 Docker 发布变量。历史空 marker 不是可部署的 XMall 应用镜像。

部署细节见 [README](../README.md)，构建依据为 [发布工作流](../.github/workflows/release.yml) 与 [GoReleaser 配置](../.goreleaser.yaml)。
